Agentic workflows, from pipelines to autonomous agents.

Six working agent patterns, two agents that run on this repository, and Erawan 1, a compact language model I built on Qwen3.

Six patterns

Each pattern is a short, runnable Python script. The first five are workflows, where code decides the steps. The last is an agent, where the model decides. Start with the simplest one that works.

01Prompt chaining

outline→gate→draft→edit

A blog-post writer that works in fixed steps. A structured-output gate checks the outline before any tokens go to the draft.

Use when the task splits cleanly into fixed stages.

View source →

02Routing

ticket→classify→billing | tech | account | general

A support-ticket router. A cheap, low-effort classifier picks a specialist, and each specialist has its own focused system prompt.

Use when inputs fall into distinct categories that need different handling.

View source →

03Parallelization

security ∥ logic ∥ style+3× vote

A code reviewer. Three focused reviews run at once (sectioning), then three independent merge votes run and approval needs all three (voting).

Use when subtasks are independent, or you want more confidence from multiple samples.

View source →

04Orchestrator-workers

plan→worker × N→synthesize

A research-brief generator. The orchestrator chooses the subtasks at runtime, workers handle them in parallel, and a synthesizer resolves any contradictions.

Use when you can't know the subtasks until you see the input.

View source →

05Evaluator-optimizer

generate⇄evaluate→PASS

A code generator paired with a strict reviewer. They loop on explicit criteria until the reviewer passes the code or the round limit is reached.

Use when success criteria are clear and iteration measurably helps.

View source →

06Autonomous agent

think→tool→observe↺

A data-analyst agent with sandboxed file access and a safe calculator. The tool-use loop is written out by hand, with a step budget and error recovery.

Use when the task is open-ended and the model has to choose its own steps.

Live agents on this repo

Two of these patterns run for real on this repository as GitHub Actions, triggered by repository events.

Issue triage routing

When an issue is opened, the agent classifies it, applies a label, summarizes it, and asks for any details a maintainer would need. Issue text is treated as untrusted input.

View workflow →

PR review evaluator

On every push to a pull request, the agent reviews the diff for bugs and security issues. It edits its own previous comment instead of posting a new one each time, and it never runs with secrets on fork PRs.

Erawan 1

A compact language model I built on Qwen3, designed to beat its 1.7B-parameter base while staying small enough to run on modest hardware.

Erawan 1 is a small model, so it can run locally or at the edge. That makes it a good fit for the low-effort steps in the workflows above, such as routing, gating and classification.

from transformers import AutoModelForCausalLM, AutoTokenizer

tok = AutoTokenizer.from_pretrained("Airavat-ai/erawan-1")
model = AutoModelForCausalLM.from_pretrained("Airavat-ai/erawan-1")
